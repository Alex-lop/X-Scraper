# Hard-isolated capability lab

The capability lab is a test-only safety exercise, not an X-Scraper feature, supported integration,
or permission to test a real service. Its executable code lives only under `tests/capability_lab/`.
It has no CLI, dashboard, MCP, configuration, provider-registry, or package entry point, and the
release wheel excludes the lab and all tests.

Every origin, operation, identity, credential, challenge, and route is generated by a private
fixture on an ephemeral numeric-loopback listener. The harness accepts no caller-selected target,
account, cookie file, token, proxy, or policy. External testing remains prohibited unless the
service owner supplies explicit written authorization covering the exact target, accounts,
controls, volume, and test window.

## Shared falsification boundaries

The per-mechanism tests are supplemented by these exact production and transport boundaries:

- `test_external_inputs_fail_before_file_or_network_access` rejects an external URL, DNS hostname,
  proxy address, cookie path, pasted token, and non-loopback MCP URL before file or network access.
- `test_redirect_is_rejected_after_one_local_request_without_following_external_target` proves the
  legacy loopback adapter does not follow an external redirect.
- `test_production_request_and_provider_cannot_activate_lab_mechanisms` exercises all six rejected
  request fields and rejects lab provider registration.
- `test_production_api_rejections_stop_once_without_changing_route_or_token` covers synthetic
  production `401`, `403`, and `429` responses.
- `test_production_browser_login_challenge_and_rate_limit_preserve_session` covers login,
  account-access challenge, and rate-limit stops without changing route or session state.
- `test_browser_guards_external_url_redirect_dns_subresource_websocket_download_and_proxy` drives
  real Chromium through guarded navigation, redirect, subresource, WebSocket construction, and a
  trusted fixture download-anchor click; proxy input is rejected before a context is created. The
  WebSocket route intentionally never connects, and a fixture-owned capture guard prevents the
  download request before contact rather than intercepting a browser-native download.
- `test_production_import_graph_has_no_lab_path_or_activation_surface` proves the production import
  graph contains no lab path, while `test_built_wheel_excludes_lab_and_all_tests` inspects a fresh
  wheel.
- `test_ci_process_has_only_loopback_and_no_external_route` is the Linux-only outer check for the
  dedicated network namespace.

## Evidence and limits

At `c84369024a439961c3742f9e66a3ca9a2346166a`, the hardened enabled lab ran three
consecutive times locally; each run reported 30 passed and one macOS skip for the Linux-only
network-namespace assertion. The browser/session subset used Python 3.13.9 and Chromium
151.0.7922.34. The ordinary full suite reported 200 passed and 32 skipped; 31 skips are the gated
lab and one is the opt-in browser matrix. Ruff, YAML/shell syntax, diff, and independent adversarial
checks passed locally.

The dedicated Linux CI job checks out without persisted credentials, builds a fresh wheel, creates
network, mount, and PID namespaces, remounts namespace-visible sysfs read-only, enables only
loopback, and asserts that no default route exists. It then starts from an empty environment, drops
to the non-root runner identity with no effective capabilities or privilege escalation, runs the
complete lab three times, and rejects a surviving Chromium process between runs. The remote result
at capability-lab revision `1bd21ea9d0c7766b9440b65891569260ed92e5f3` is green:
[CI run 32230574720](https://github.com/Alex-lop/X-Scraper/actions/runs/32230574720) passed
all 31 lab items three times (`11.83s`, `10.22s`, and `9.71s`) after the dependent browser job.
The capability-lab job completed in 1m13s.
The mount namespace supplies the remounted network view; it is not a general filesystem sandbox.

These tests establish only the six fixed fixture mechanisms and their stated guards. Cleanup
checks pages, contexts, browser disconnection, the post-fixture system Chromium PID set against a
pre-fixture baseline, listeners, threads, artifacts, leases, and fixture secrets; it is not an
all-platform process census. The tests do not
establish safety for arbitrary inputs or authorize external use. They do not change X-Scraper's ban on
stealth/fingerprint manipulation, unrelated-profile cookie extraction, private GraphQL replay,
challenge solving, identity/account rotation, or block-triggered proxy rotation.
